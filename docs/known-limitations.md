# 已知限制与技术风险

本页区分当前实现边界和需要后续验证的风险，不把建议描述成已交付能力。

## 产品限制

| 限制 | 影响 |
| --- | --- |
| 无账号、云同步、多用户或移动端 | 适合单用户本地工作流 |
| PDF、DOCX、PPTX 不编辑源文件 | 以阅读、标注、提取和保存 Markdown 为主 |
| 资料浏览器最多 10 个标签 | 不是通用浏览器 |
| 无浏览器扩展、密码管理、复杂下载或视频支持 | 资料浏览功能刻意受限 |
| 仅内置可信插件 | 没有第三方插件市场 |
| 本地词法索引 | 不是向量检索或托管 RAG 服务 |
| AI/OCR/图片生成可能出错 | 重要内容必须回看原始资料 |
| 本地语音和系统日历仅 Apple Silicon macOS | Windows/Linux 能力不完全对称 |

## 分发与运维风险

- 安装包尚未进行 macOS 签名/公证、Windows Authenticode 或 Linux 发行版签名。
- 没有应用内自动更新、发布 feed 或自动回滚；安全更新依赖用户手动下载安装。
- 常规 CI 不运行完整 Playwright；UI、IPC、持久化和桌面交互需要本地或 Release smoke 证据。
- Release 使用平台 Runner 构建，但真实签名凭据和目标硬件权限仍需发布负责人验证。

## 数据与隐私风险

- 项目内 `.coscribe`、用户级最近项目和浏览器历史可能含路径、会话、批注或登录态。
- AI 操作历史为支持撤销保存前后正文，备份与问题报告需脱敏。
- 研究浏览器持久化 Cookie/localStorage；清空历史不一定等同清空所有站点状态。
- JSON 文件存储透明易复制，但不提供数据库事务或跨进程并发协调。

## 外部服务风险

- OpenAI-compatible Provider 的模型发现、流式格式、工具调用和 reasoning 字段并不总是兼容。
- MCP 可以启动本地进程或访问远程 HTTPS；即使配置加密，用户仍应把其视为高能力显式工具。
- 图片生成只发送用户明确的 prompt、size、quality，不会自动带整段会话历史；产品文案不能暗示相反行为。

## AI Shell 风险

AI Shell 以当前登录用户权限执行命令，不受项目文件夹沙箱限制。默认关闭、两次原生确认、默认逐条确认、内存态项目授权、输出清理和长度限制能减少误用，但不能使高影响命令变为安全操作。

会话授权模式会降低逐条确认强度。未来不得把 AI Shell 改成静默、后台或跨项目持久化授权。

## 技术演进风险

- `App.tsx`、`electron/main/project.ts` 和 `electron/main/ai.ts` 的职责面较大；拆分前先锁定行为与回归测试。
- 项目内 `.vibeknowledge` 的可兼容数据会导入 `.coscribe`，但旧目录会保留以避免静默修改 Git 工作树；用户级 `vibeknowledge` 路径仍为兼容包袱，不要把两者混为同一迁移。
- Electron、原生 `node-pty`、OCR/ASR 资源和跨平台打包依赖升级后必须重新验证全部目标平台。

建议优先级、商业化、签名证书负责人、隐私政策、数据保留期和正式 Provider 支持矩阵需要产品/运营/发布负责人明确，不能从代码推断。
