# 运维与排障

## 运行形态

CoScribe 是本地 Electron 桌面应用，没有自建云后端。AI、DOI、网页、MCP 和图片生成等能力只在用户明确配置或触发时访问外部服务。

支持问题应先明确：

- 应用版本、操作系统、架构和安装方式。
- 是否是源码开发、未打包目录或正式安装包。
- 是否涉及本地文件、AI Provider、MCP、终端、OCR、语音、浏览器或插件。
- 可复现步骤、预期行为、实际行为和已做的排查。

不要上传 API Key、`settings.json`、完整 userData、浏览器 Cookie、私有项目文件、真实聊天内容或 `.vibeknowledge` 原始元数据。

## 常见问题

### AI 无法发送或自动补全不出现

1. 确认“设置 → AI 服务商”中已有已启用的模型。
2. 检查服务地址：远程服务必须 HTTPS，本地服务才可使用 HTTP 回环地址。
3. 使用“获取可用模型”确认 Provider 返回的模型名。
4. 代码补全还需确认“设置 → AI 行为 → 启用 AI 代码补全”。
5. 自动补全在有效代码输入停顿后出现；选择文本、移动光标、继续输入或未配置 Provider 时不会保留旧建议。

### AI Shell 入口不可用

1. 打开“设置 → AI 行为”并启用 **AI Shell 功能**。
2. 回到 IDE 底部终端点击“开启 AI Shell”，阅读风险警告并完成第二次确认。
3. 默认每条命令仍需批准。
4. 关闭终端、项目、应用或设置开关都会撤销授权，需要重新开启。

“启用 AI Shell 功能”不是执行授权；它只显示开启入口。详见 [安全与 AI Shell](./security-and-ai-shell.md)。

### 内置终端无法启动

- 确认当前项目路径仍可访问。
- 开发环境执行 `npm install` 或 `npm run build`，它会修复 `node-pty` helper 的可执行位。
- 打包应用运行 `npm run verify:package:mac` 或对应平台校验。
- 外部终端失败时可继续使用内置终端；Windows 需要 `wt.exe`，Linux 会按常见终端候选顺序尝试。

### macOS / Windows 阻止应用启动

当前安装包尚未完成平台签名和公证。请只从官方 GitHub Release 下载，并先核对 `SHA256SUMS.txt`。

- macOS：Finder 右键应用选择“打开”；必要时在“隐私与安全性”中确认。
- Windows：确认下载来源和校验和后，再通过 SmartScreen 的“更多信息”继续。

不要从未知来源下载同名安装包，也不要关闭系统全局安全防护。

### OCR、语音或截图不可用

- OCR 依赖随包资源和当前资料格式；先确认文件可在应用中正常打开。
- 截图需要操作系统授予屏幕录制权限。
- 本地语音当前仅适用于 Apple Silicon macOS，需要麦克风权限。
- Windows/Linux 没有本地语音和系统日历同步属于当前产品范围，不是一般故障。

### 项目元数据损坏或无法恢复

原始资料仍是项目普通文件。先复制项目做备份，再检查 `.vibeknowledge/` 是否被外部程序替换为目录、只读文件或损坏 JSON。应用会尽量以安全默认值启动，但会话、布局、OCR 或操作历史可能需要从备份恢复。

## 维护操作

- 更新依赖或 Electron 后重新验证 `node-pty`、ASR、OCR 和三平台包。
- 发版前在原生系统构建，运行 package verify 和包后 smoke。
- 使用 GitHub Actions 保存失败时的 Playwright trace、截图和视频；不要公开其中的真实用户数据。
- 引入崩溃上报、自动更新或遥测前先定义隐私、脱敏、保留期、用户同意和回滚策略。
