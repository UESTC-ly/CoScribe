# Auto Research MVP

CoScribe 的“文献与引用”插件现在支持一条后端驱动的研究流程：输入主题，检索公开论文与 GitHub 仓库，选择资料后导入文献库，尝试下载 PDF 或 README，最后预览并确认保存文献笔记和主题综述。它适合开始了解一个领域；有限的候选检索不能代替完整的系统综述。

## 使用方法

1. 在插件中心启用“文献与引用”，补充网络访问授权。如果要让 AI 规划检索词或生成草稿，再补充 AI 请求授权，并在设置中配置模型。
2. 在 **Auto Research · 主题研究** 输入主题，选择 Crossref、arXiv、GitHub，每个来源选择 1–10 条，默认 5 条。可启用 AI，将主题转成英文检索词；模型失败时保留原始主题并显示原因。
3. 等待候选就绪，选择最多 8 条，点击“导入选中资料”。默认尝试下载资料，也可以只导入元数据。
4. 选择一条已导入资料，点击“预览文献笔记”；选择 1–8 条已导入资料，点击“预览主题综述”。未启用 AI 时生成可填写的 Markdown 模板。
5. 检查草稿后点击“确认保存草稿”。文件在 `研究/Auto Research/<任务 ID>/`，与既有笔记分开保存；可从任务中的快捷入口或文件树重新打开。

AI 选项会把主题及选中资料的证据摘录发送给已配置模型服务。此流程不注入个人记忆，也不把论文、README、模型输出写入个人自动记忆。取消、项目切换、关闭项目或设置变化会中止正在进行的任务；设置变化后需要重新发起相关操作。应用重启不会自动重放网络请求和导入；未结束的任务显示为中断，可手动重试导入。

## 来源与下载

| 来源 | 检索内容 | 导入内容与限制 |
| --- | --- | --- |
| Crossref | 题名、DOI、作者、年份、期刊及可用摘要 | 元数据；不把登记的出版社链接当作已确认的开放 PDF |
| arXiv | API 返回的论文与摘要 | 元数据，并尝试下载规范 arXiv PDF 地址 |
| GitHub | 公开仓库及描述 | 元数据，README 快照记录 blob SHA 与获取时间；不克隆、运行或解压仓库代码 |
| GitHub MCP（可选） | 已配置服务的 `search_repositories` | 结果经过同样的仓库身份校验；下载仍通过固定的 GitHub API |

检索依据 [Crossref REST API](https://www.crossref.org/documentation/retrieve-metadata/rest-api/)、[arXiv API](https://info.arxiv.org/help/api/user-manual.html) 和 [GitHub Repository Search](https://docs.github.com/en/rest/search/search?apiVersion=2022-11-28)。arXiv API 请求间隔至少 3 秒。公共 GitHub API 不需要为这个功能额外保存 token，但可能达到未认证请求限额；403、429 等错误会显示为检索或下载缺口。

首版使用内置 `auto-research-v1` 工作流与固定提示词，不要求先安装第三方 Skill/MCP。已有 MCP 连接器可以接入 [官方 GitHub MCP Server](https://github.com/github/github-mcp-server)，推荐启用其 `--read-only` 模式，限定 `repos` 工具集。远程服务可按官方配置设置 `X-MCP-Readonly: true`。在 MCP 连接器完成配置与授权后，研究面板可选择该服务。工具必须声明 `annotations.readOnlyHint: true`，否则自动调用会被拒绝；不会执行服务提供的提示词或任意其他工具。凭证沿用 MCP 连接器的系统安全存储，不写进项目。

## 证据与生成

生成使用现有 AI 配置，兼容 Chat Completions、Responses 和 Anthropic Messages。模型没有文件、Shell、浏览器或任意 MCP 工具权限。外部摘要与 README 被作为资料数据提交，不能授权额外动作。

每条 AI 结论必须给出输入证据 ID 和逐字存在的原文引文，主进程验证后才能产生草稿。验证只证明引文存在，不证明模型对原文的解释正确，所以仍需人工核对。不存在的证据 ID 或虚构引文会使草稿生成失败。

PDF 最多提取前 8 页，每页最多 2000 字符、每篇最多 8000 字符；文档注明总页数和本次采样范围。摘要最多取 4000 字符；README 最多取 8000 字符。无法提取的 PDF、缺少摘要、作者声明与全文采样都会明确列出。没有可读证据时无法生成 AI 结论，但可以创建手工模板。综述引用键来自实际导入记录，并附来源清单和可核对的证据摘录。

## 存储与保护

- 任务状态：项目 `.coscribe/research-runs.json`，保留最近 10 个任务，超出 2 MB 时先移除最旧任务记录，项目中的资料和草稿文件不删除。
- 文献库：继续使用 `.coscribe/plugin-data.json` 中的 `references`，增加 `revision` 以检测旧界面的覆盖写入。旧版本无 revision 的库按 0 读取。
- 文献去重：优先稳定 ID、DOI、来源 URL；自动导入只补充缺失元数据，保留已有题名、批注和标签。同名引用键的不同文献分配不同键。
- 下载文件：`研究/资料/`；PDF 按内容摘要命名，README 按仓库身份与 blob SHA 命名。重复导入不覆盖同名文件。失败后文献元数据仍可保留，用户可显式重试下载。
- 检索记录：在导入任务中保存实际来源、规划检索词、执行查询、时间、候选与每项下载结果。只有元数据的条目不会被标记为已读全文。
- 主进程只访问固定 HTTPS 来源；手动校验重定向，不接受来自候选或模型的任意下载 URL。检索响应限制 2 MB、PDF 20 MB、README 512 KB，每次导入 PDF 总量最多 100 MB。
- 写入绑定项目生命周期和设置版本，使用既有项目根目录、符号链接检查与原子创建。草稿预览缓存 30 分钟、最多 20 份，确认时只接受主进程生成的 ID。
- 插件数据更新串行执行；损坏的文献/任务 JSON 不会被默默清空。授权检查和窄 IPC 延续现有插件安全边界。

## 当前范围

首版没有 Semantic Scholar/OpenAlex 等需要额外账户配置的连接器、引用追踪、多轮无限研究、全仓库代码下载与分析、扫描 PDF 自动 OCR、后台定时研究、自动续跑、正式 PRISMA 筛选或引用格式排版。检索结果按提供方相关性排序，AI 只规划检索词与生成有证据的草稿。已有综述矩阵仍可读取新导入的文献库。

## 验证

测试覆盖固定来源与重定向限制、响应大小、arXiv XML 实体拒绝、GitHub 仓库身份、只读 MCP、三种 AI 协议、证据引文校验、下载部分失败与重试、保留批注、引用键冲突、并发库写入、取消、授权变化、跨项目写入拒绝、符号链接和中断恢复。桌面端使用可控的来源/模型响应验证检索、导入、模板/AI 草稿、确认写入和重启恢复；不能据此保证第三方服务随时可用。

本次验收：`npm test` 共 416 项通过（112 unit、266 Electron/main、38 AI）；完整桌面回归 48 项通过、2 项条件跳过（成品包 smoke、真实 ASR）。生产构建与类型检查通过。新增真实 9 页 PDF 用例覆盖前 8 页研究摘录、原有第 9 页读取及 PDF.js 资源释放兼容性；公开 Crossref、arXiv、GitHub 检索接口各做一次少量查询，均返回 HTTP 200 和可用记录。真实第三方模型与需要用户凭证的官方 GitHub MCP 尚未在线验收；MCP 使用本地只读服务测试协议。
