# 个人助理 MVP：记忆、活动账本与每日复盘

实施日期：2026-10-07。依据交接文档推进后端优先的最小实现。显式个人记忆已完成，第二步加入新对话自动记忆、项目活动账本、每日复盘草稿与确认写入。实现不代表交接文档的全部阶段已完成。

## 使用入口

**设置 → 关于我**：明确填写表达偏好、个人信息或当前目标；查看来源、修正与二次确认遗忘。此页即时保存，使用“关闭”退出。召回、向远程模型发送、自动提取候选、自动保存学习状态均为独立开关，默认关闭。

**插件 → 每日笔记与模板 → 每日复盘**：启用插件后，可单独开启本项目活动记录；选择日期和 IANA 时区，补充实际完成、未解决问题或个人反思，选择是否读取项目计划，生成草稿。点击“预览写入复盘”核对完整文件内容，再“确认写入复盘”。默认文件为 `每日笔记/YYYY-MM-DD.md`，也可指定项目内其他 Markdown 文件。

生成、预览都不创建笔记或目录。重复生成相同日期、时区和输入得到同一持久化草稿；相同草稿再次确认不会增加重复区块，也不会重复改写文件。后台定时复盘与自动发送通知尚未实现。

## 个人记忆

个人记忆属于用户全局数据，不写入知识项目。已确认正文保存于 Electron `userData/assistant/memory/<稳定 ID>.md`，SQLite 保存索引、来源、版本、授权及经文件核对的正文缓存。每条有程序生成的来源 ID、记录时间和版本。请求不能伪造来源、工作区或信任标签。存储、迁移和分层召回详见 [个人记忆检索](./personal-memory-retrieval.md)。

显式新增由用户在“关于我”中填写。自动提取仅处理正常聊天本次直接提交的最后一条用户正文，不扫描历史会话、导入聊天、引用文件、附件、选区、模型输出或召回内容；压缩、整理笔记和生成计划等专用请求不进入自动记忆。聊天中的已有“记住”项目记忆行为保持独立。

自动提取采用确定性的本地中文规则。例如“我正在学习图论”可产生目标，“我是计算机专业学生”可产生个人信息，“以后请用中文讲解”可产生偏好。含引用、代码块、假设、问题、外部来源或密钥线索的输入不提取。首版有意仅支持少量明确句型，不能保证识别所有自述。

默认提取结果作为候选保存原文、会话来源和时间，用户可确认或忽略。偏好和个人信息始终需要确认；单独启用“自动保存明确的学习状态”后，只自动保存没有已有同类冲突的非敏感学习自述。敏感状态和冲突保留候选。用户可明确选择新增并保留旧条目，或使用旧条目的版本确认替换。模型没有个人记忆写入工具。

同一会话输入与候选正文去重。修改或遗忘会删除旧来源与检索项、清理相关候选，并记录不含正文的来源/事实排除指纹；旧自动任务和相同学习主题的换句自述不能自动恢复已修正或遗忘的信息。忽略候选也会留下排除指纹。用户主动显式新增仍可重新记住。撤销或调整自动授权清除旧授权候选，旧代次任务不可在新授权下提交。原始聊天、独立活动账本、已导出的笔记以及迁移/系统备份不会因遗忘一条记忆被删除。

首层召回最多四条偏好和三条相关个人信息摘要，偏好预算 1,500 字符，非偏好摘要每条最多 180 字符，个人与学习状态数据总预算 4,000 字符。模型可通过只读 `memory_search` 搜索摘要，再通过 `memory_read` 按 ID 和版本展开当前正文与来源。默认用 FTS5 / BM25 和有限别名；可在设置中显式配置 embedding，补充向量候选并按排名融合，远程 embedding 遵守同一独立授权。最多 500 条记忆、200 条待确认候选，每条显式记忆最多 1,000 字符。

普通聊天只有开启召回后才注入个人记忆，不扩大文档/选区范围，不把用户自述作为文献证据，也不授予工具权限。远程发送默认关闭：额外召回仅能发送到本机回环地址。此开关不控制用户主动提交的聊天和项目资料，也不保证本机模型不会自行转发。记忆与授权变更取消进行中的 AI 请求，每次模型网络调用前再检查使用的全局记忆版本；已发出的网络数据无法撤回。

## 活动记录与复盘

活动记录授权按主进程绑定的项目根目录隔离，并带有独立代次和开启时间。它独立于个人记忆召回/自动提取开关；停用界面插件不会代替撤销此前单独开启的活动记录授权。应在复盘页关闭记录，或清理账本。

自动记录范围为开启授权之后、通过上下文检查的正常聊天用户提交，以及通过应用文件保存/创建接口成功写入且内容发生变化的 Markdown 笔记。对话保存用户输入摘要（前 900 字符）及会话定位；笔记保存事件仅保留相对路径，不复制笔记正文。没有记录附件、模型答案、文件打开、旧会话导入、系统日历、邮箱、外部编辑、AI 文件建议确认或插件直接内部写入。复盘自己的确认写入也不记为新的学习活动。文件成功保存后账本失败不会把文件操作报成失败，返回明确 warnings。

手动补充可在自动记录关闭时使用，属于用户主动自述。日期和时区决定归属日，不伪造精确事件时间；同一提交 ID 重试去重，内容变化则拒绝复用 ID。每项目账本最多 10,000 条；一份草稿最多取当日最早 500 条，超出会显示覆盖缺口。

日期按 IANA 时区计算真实本地日边界，支持 23/25 小时的夏令时日，拒绝无效日期、时区和历史上被时区跳过的日期。草稿在事务中冻结活动、计划与授权快照指纹，保留来源编号和固定 Markdown。新增活动或计划变化生成新草稿，旧草稿不被回填。

复盘明确分开：对话/笔记活动、用户报告的实际完成、未解决问题、计划与实际对照、明日已知安排、建议和覆盖缺口。打开文件不等于学习，对话不等于掌握；计划表里的“已完成”只是计划状态，不能作为实际完成证据。只有勾选对照项目计划时才读取 `计划/项目计划.md`，从现有表格解析本日/次日安排；不虚构外部日程。生成过程不调用模型或额外联网。

“清理本项目活动账本”删除本项目活动、草稿及写入凭据，关闭自动记录并递增授权代次。其他项目和个人记忆不受影响，已有笔记保留。清理后旧导出区块失去所有权凭据，程序不会自动覆盖它们。

## 预览确认与恢复

复盘使用日期与时区唯一的 managed Markdown 区块，只追加或替换自己的区块，精确保留区块外的人工文字及空白。此前确认的区块内容哈希必须匹配，区块内人工修改、标记缺损/重复或无法证明所有权时拒绝覆盖。文件整体变动会使已生成预览失效，需重新预览。

预览只接收草稿 ID 和目标路径；确认只接收主进程缓存的预览 ID，不接受 Renderer 改写后的正文。通用 AI 操作确认接口不能接受复盘预览，避免绕过复盘写入日志。应用重启后旧内存审批失效，必须重新预览。

确认前持久化 `prepared` 写入凭据，再通过项目现有路径/符号链接防护、文件版本检查和原子创建/替换写入，验证内容后记为 `committed`。写入过程中同步检查项目生命周期和主进程授权代次，防止项目切换或撤销授权后的待处理写入继续生效。复盘导出不进入现有 AI 操作历史/撤销列表，保留正文应通过笔记编辑或外部备份管理。

SQLite 和 Markdown 没有跨存储原子事务。中断后下一次预览将实际磁盘内容与准备日志比对：写入前内容匹配则重新预览；写入后内容匹配则核对完成；两者都不匹配或授权已变化则停止并提示检查原文件/另选目标。不会盲目重放文件写入。存储 worker 超时不自动重试，需要重启并核对结果。

## 后端与接口

`electron/main/assistant/` 包含严格 schema、SQLite repository、自动记忆规则、复盘规则、写入协调器和串行存储 worker。共享 DTO 在 `src/shared/assistant.ts`，由具名 IPC 与 preload 暴露；所有请求沿用主窗口 sender 校验。Renderer 没有 Node 权限，不能自行指定账本工作区或应用事件来源。

| API | 行为 |
| --- | --- |
| `assistant.memory.list()` | 条目、候选及召回/自动授权状态 |
| `remember()` / `update()` / `forget()` | 显式保存、带版本修正和遗忘 |
| `setPolicy()` | 带全局版本的召回/远程授权 |
| `setSearch()` / `rebuildIndex()` | 配置可选 embedding 服务；从已登记 Markdown 重建派生检索索引 |
| `setAutomatic()` | 带自动代次的候选提取/学习状态保存授权 |
| `resolveCandidate()` | 确认、忽略或显式指定旧条目版本替换 |
| `assistant.review.policy()` / `setPolicy()` | 当前项目活动授权与代次 |
| `addActivity()` | 用户选定日期、时区、类型、正文与去重 ID |
| `generate()` | 日期、时区、是否对照计划 → 固定草稿 |
| `prepareExport()` / `commitExport()` | 草稿/目标 → 预览；预览 ID → 确认写入 |
| `clear()` | 按当前代次清理本项目账本、草稿与凭据 |

复用 Electron 43.1.1 的 Node 24.18.0 / SQLite 3.53.1，不增加数据库依赖。专用 worker 采用短事务、外键、WAL、FULL 同步、安全删除。目录 0700、数据库与 sidecar/迁移备份 0600。数据库自身符号链接被拒绝，未知/较新 schema 或损坏库保留原文件并关闭助理存储，普通聊天仍可使用。

当前 schema 为 4，旧库依次执行迁移：1 → 2 加入工作流，2 → 3 加入学习库，3 → 4 将已确认个人记忆正文写入 Markdown 并建立文件核对记录。各旧版本升级前用 SQLite `VACUUM INTO` 保存一致备份，新安装不建立空库备份。Markdown 与 SQLite 通过持久化 outbox 及前后哈希核对恢复中断操作；未知内容冲突不覆盖原文件。旧 JSON/项目记忆/聊天不会自动搬入新库。迁移备份包含迁移当时的原始记忆，后续遗忘不会修改它；可在确认无需恢复后自行管理该文件。本版没有备份恢复/导出界面。

正文未加密；API 凭据仍由原有安全存储管理，不进入助理库。安全删除与 WAL 截断不能承诺物理擦除文件系统快照或其他副本。

## 验证范围

新增后端回归覆盖本地抽取、来源隔离、默认关闭/独立授权、冲突确认、遗忘/修正/忽略后的排除、撤销与旧任务、账本跨项目隔离、日期/时区/夏令时、固定草稿、计划不当作事实、人工内容保留、通用确认绕过拒绝、文件/项目/授权冲突、原子写入中的撤销，以及文件写入前/后/未知状态和 SQLite 完成日志失败的恢复。真实 v1 库的备份/升级与失败回滚也有测试。

桌面测试使用隔离 userData 与本地 mock 模型，验证界面授权、自动保存学习状态、人工确认偏好、模型输出不成为事实、遗忘不复活、重启持久化；验证活动记录、计划对照、复盘草稿、预览无写入、确认保留手写文字、重复导出无重复区块和人工修改冲突。测试产物包含实际界面截图。

直接 SQLite 测试需要宿主 Node 22.13+（推荐 24+），Node 20 会明确跳过 SQLite 测试组，不能将跳过算作验收；Node 20 仍可构建，生产 SQLite 运行在 Electron worker。当前 macOS arm64 宿主 Node 26.8.1；应用 Electron 43.1.1 / Node 24.18.0。

以下为此前个人助理工作流阶段的验证记录，不代表后续学习库与 Markdown 记忆改动的当前全量结果。本轮按用户要求只做相关后台回归与类型检查，不启动软件；范围见 [个人记忆检索](./personal-memory-retrieval.md)。此前执行 `npm test` 和 `npm run test:e2e`（包含类型检查与生产构建），2026-10-07 记录如下：

目前已实现受限的只读记忆工具循环与可选 embedding；尚未实现通用工具运行账本、后台整理调度、外部日历审批、邮箱接入、语义级遗忘或模型驱动记忆提取。未调用真实云模型或 embedding 服务、用户邮箱/日历，未进行跨平台签名安装包验证。下一步应根据实际需求推进持久化工具运行记录或受控复盘调度；涉及日历/邮箱写入前需单独实现外部审批与恢复协议。

## 学习与复习扩展（2026-10-07）

全局助理库在 schema 3 引入结构化知识点、技术关注、学习阶段、用户自评和独立复习事件，当前 schema 4 保留其事务存储；详见 [个人学习状态与复习后端 MVP](./learning-review-mvp.md)。这些数据可通过“关于我”查看、纠正、删除，受相同的召回与独立远程授权约束。复习插件额外明确申请读取／写入全局学习库权限；旧闪卡通过显式导入保留进度。原自动记忆的学习自述仍作为 `goal`，没有自动转换为新能力事实。
