# 个人学习状态与复习后端 MVP

实施与核对：2026-10-07。首轮范围是个人学习库、明确学习依据、知识关联、到期查询与手动复习，以及受记忆授权控制的助理召回。后台通知和周期任务未实现。

## 用户流程

启用“闪卡与间隔复习”，在插件中心明确授权 `learning:read` / `learning:write` 后，创建知识点，填写所属领域，再关联当前阅读文件、已保存选区、文献 ID 或当前项目。界面可使用当前阅读／选区预填来源，也可手填项目内路径。选区原文必须能在已保存文本中核对；PDF 选区必须有页码且能提取正文。未保存内容需要先保存。

分别记录技术关注、学习阶段和用户自评。每个知识点每类状态只有一条当前记录；再次明确记录同类状态会更新该记录的来源、时间与版本，保留稳定 ID。它们分别表示“关注”“学过”“用户自述掌握”，不会由阅读时长、聊天次数、外部文本或模型评价推定。复习反馈是另一类依据，独立保存为事件，不修改自评或邻接知识点状态。

可以建立前置知识、组成、对比、应用关系，标明用户整理或模型建议及依据来源。关系先保存为待确认；题目可使用这些关系组织对比或应用练习，题目也先待确认。先确认关系、再核对问题与参考答案并确认题目，才进入队列。修改关系或题目撤销受影响题目的确认，不清除其复习历史。关系端点改变后，失去关联的材料会移除该关系，并要求重新确认。

今日队列查询到本机当日结束；显示答案后提交“重来、困难、记得、简单”。也能在材料中手动复习尚未到期题目。时间由主进程／存储进程生成，复用现有闪卡间隔算法。单次成功只记录目标题目的知识点表现。复习证据可以纠正或删除，相应材料会从导入种子和保留事件重新计算调度。

设置 → 关于我 → 个人学习数据，可以在插件停用、授权撤销或项目关闭后继续查看、纠正和删除。插件授权负责插件访问全局学习库；普通聊天使用学习状态仍需要“回答时使用个人记忆”，远程发送还需要独立远程记忆授权。停用复习插件不等于撤销个人记忆召回授权。

## 数据与一致性

数据沿用 Electron `userData/assistant/assistant.sqlite`，不写入项目。助理数据库 schema 升至 3；从 schema 2 升级前用 `VACUUM INTO` 保存受限权限备份（含已提交 WAL）。从 schema 1 升级保留原 v1 备份，不重复备份中间版本；新库不生成迁移备份。旧备份、系统快照与主动导出的文件不会随删除自动清除。

首版用 `learning_state` 单行保存严格验证的聚合 JSON。SQLite `BEGIN IMMEDIATE` 事务同时写入知识／记录／关系／材料／事件／提交凭据和全局个人记忆版本。所有修改携带整体 `expectedRevision`，不同窗口的并发旧版本只能一个成功；冲突不覆盖其他操作，需刷新核对。聚合上限 4 MB，知识点最多 500、来源／状态／关系／材料各 2,000、事件 5,000、提交凭据 10,000。达到上限明确拒绝，不自动删历史。后续扩容需要新的迁移。

| 对象 | 标识与关键字段 |
| --- | --- |
| 知识点 | UUID、名称、领域、来源 ID、创建／更新时间、修订号。名称与路径不参与身份 |
| 来源 | UUID、主进程绑定的项目根、根摘要 `workspaceId`、项目名、相对路径／文献 ID／页码／行号／选区、内容指纹与修订 |
| 学习状态 | UUID、知识点 ID、`interest` / `stage` / `self-assessment`、值、用户说明、来源、`user-explicit`、时间与修订；同类更新原记录 |
| 知识关联 | 两端 UUID、关系类型、资料来源或手动整理说明、`user` / `model`、确认时间、修订 |
| 材料 | UUID、目标题点、问题／答案、来源与关系 ID、确认状态、当前调度、算法版本 |
| 复习事件 | UUID、提交 UUID、知识点／材料 ID、材料与来源修订、反馈、发生／修正时间、下次时间、`coscribe-sm2-v1` |
| 内部凭据 | 导入映射、导入调度种子、幂等提交凭据；删除后仅留不含正文与反馈的防重标识 |

重复反馈先核对提交 UUID：相同未纠正事件的同一载荷返回当前状态，不再增加事件或间隔；复用 UUID 改变反馈被拒绝。事件被纠正或删除后，旧提交不得恢复它。事件、材料或知识点删除同时清理对应正文与检索使用数据，保留防重标识。用户纠正会删除旧当前状态正文，修订号反映变化；不保存每版正文副本。

## 项目、移动和失效来源

项目关闭或切换时，不访问其他项目磁盘；知识、自述、确认材料和复习事件仍可跨项目使用。来源显示“来源项目未打开”，不是已验证可用。当前项目来源通过现有 `ProjectPathGuard` 检查普通文件、范围与符号链接，再按限额读取和核对指纹。文件缺失、内容变化、文献删除或访问失败分别提示。来源读取期间项目／授权变化会拒绝后续提交。

文件改名或移动不会改变知识点与材料 UUID。原定位失效时，用户可在原项目“重新关联来源”，保留来源 ID 与复习历史。题目措辞修改保留材料 ID／调度，需再次确认。整个项目根移动不会自动推断身份，旧定位显示项目未打开；可在新位置附加新来源，明确修改材料来源并删除旧定位。没有自动扫描磁盘找回文件或跨项目重绑来源。

选区支持已保存文本笔记、代码和可提取文字的 PDF，不支持扫描图像 OCR 验证。文献关联校验当前项目文献库 ID，指定文件时还需与其 PDF 关联一致。来源可失效，已确认的独立复习材料仍可使用；界面提示失效，复习结果仍仅作为用户本次反馈。

## 旧闪卡兼容

旧 `.coscribe/plugin-data.json` 的 `flashcards.reviews` 不删除、不覆盖，作为原始兼容副本保留。用户主动“导入项目 Markdown 闪卡”后，主进程解析实际文件，以旧绝对路径加 Q/A 计算的旧 ID 对应旧调度；在同一事务创建稳定 UUID、来源和导入映射。导入保留到期时间、间隔、ease、次数和最后时间，不补造没有依据的历史事件，不把旧次数当成近期掌握证据。

同项目同旧 ID 只导入一次，不覆盖新进度；删除后的旧 ID 不会因再次导入自动恢复。找不到文件或已改变措辞的旧进度会返回 `unmatchedReviewIds` 并显示 ID，原记录仍保留。新版界面以全局后端调度为准；不再通过 Renderer 覆盖写旧复习 JSON。未授予新增权限的旧安装不会被静默授权，需补充授权。首次导入前若原文件已经改名／改题，首版不能自动匹配旧哈希，应先核对或恢复原始文件。

## IPC 与助理召回

共享契约在 `src/shared/learning.ts`，`AssistantAPI.learning` 由 preload 暴露；通道集中于 `electron/ipc-channels.ts`。主窗口 sender 校验沿用 IPC 总入口。没有新的模型写入工具、任意 IPC 或 Renderer Node 权限。

| API | 范围 |
| --- | --- |
| `list`、`due(through?)` | 插件 `learning:read`；列表核对当前项目来源时还需 `project:read` |
| `mutate` | 严格、有限的知识／来源／状态／关系／材料／反馈命令；`learning:read` + `learning:write`；来源操作额外需 `project:read` |
| `importLegacy` | 显式指定最多 100 个 Markdown 路径，至多 500 张；校验旧 JSON、项目范围、版本和授权 |
| `inspect`、`correct` | 核心个人数据管理；不读取来源磁盘，`correct` 只允许纠正／删除已有数据，不允许添加、确认关系或提交复习 |

对全局数据的提交在获授权后进入串行存储队列；来源与导入读取期间持续检查项目和设置版本，不在新授权下接受旧工作。设置保存期间拒绝新的插件操作，异步授权读取也核对版本，防止撤权写入尚未完成时使用旧设置。核心个人数据管理仍可用。已确认提交可能在响应前完成，超时不自动重试，需先核对。写入学习数据同样停止进行中的 AI 请求；学习修改与记忆／授权修改一起递增召回版本，每次模型网络调用前再检查。已经发送的数据无法撤回。

学习状态首层召回采用名称／领域词法相关性和有限别名：挑选最多六个相关点，学习 JSON 最多 2,000 字符，和个人记忆共同最多 4,000 字符。模型也可通过只读 `memory_search` 查知识点摘要，再 `memory_read` 按 ID 和版本展开当前证据；详见 [个人记忆检索](./personal-memory-retrieval.md)。分别提供当前关注／阶段／自评，及最近 30 天最多三条复习证据、时间、版本和来源定位元数据。来源可用性标为本次未核对，不向模型声称外部资料已验证；不发送来源选区、资料正文、题目答案、用户说明或项目绝对根路径。模型输出、外部文献、网页或邮件没有个人学习事实写入入口。

## 后续方案与已核对缺口

**A. Auto Research 可靠性。** `electron/main/research/service.ts` 已有 `Job.busy`、状态写队列、授权／项目版本检查、取消及重启后 `interrupted`；不是完全没有互斥。但 import/draft 的忙检查和设置之间存在异步授权，需用覆盖整个操作的后端锁或串行入口验证竞态。逐项下载失败会保留元数据和 `downloadStatus`，最后仍可能进入 `completed`；它表示流程走完，不能表示所有下载成功。资料文件、文献库、run 和检索日志分多次写入，无跨文件事务或完整导入日志，崩溃后需核对文件指纹／引用 ID 再决定重试。PDF 提取接口尚无 AbortSignal，取消后结果会被版本检查拒绝，但解析本身不立即停止。界面需区分操作成功、部分成功、取消、中断、需核对和状态持久化失败，并以实际后端结果为准。下一步补全程互斥、逐项持久化凭据、核对／重试与 PDF 取消测试，不在本轮修改研究流程。

**B. 科研与学习连接。** 本轮支持文献来源定位和人工确认关系／材料，但没有从笔记／综述自动生成学习候选。后续由研究插件提议带证据 ID 的知识点、关系与题目，再通过明确确认进入全局库；资料结论与用户能力仍分开。

**C. 邮件与日程。** 邮件提供方尚未选定，也没有实现邮箱读取。本轮不访问邮件或日历。下一阶段先确定一个提供方、账户、时间窗口，只读提取并预览候选；日历写入需独立确认、操作 UUID、外部事件 ID、去重和结果不明确后的查询核对。现有一次写入命令不足以支持可靠外部同步。

**D. GitHub 周报。** 先复用公开检索，实现用户关注配置和按需摘要，保存实际查询、时间窗口、抓取时间、来源与统计口径。总星标不能表示周增长，检索排序不能称官方 Trending。历史快照、周期执行、持久化失败记录与通知另行实现。

其余限制：没有后台通知、周期调度、FSRS、遗忘概率预测、知识图谱自动推理、学习状态的 embedding 索引、自动掌握分数、来源自动搬迁、学习 JSON 导出按钮或大规模数据分页。个人记忆正文可单独配置 embedding。现有自动学习自述仍是原 `goal` 记忆规则，不会静默转换成新结构化能力事实；全局学习状态以本轮显式记录与手动复习为入口。
