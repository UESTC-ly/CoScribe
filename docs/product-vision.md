# CoScribe 产品主线与 MVP 顺序

更新：2026-10-07。本文件记录用户明确提出的产品方向，并区分现有实现与后续设计；功能是否可用仍以源码和对应 MVP 文档为准。

产品定位：**理解你正在读什么，了解你的身份与技术积累，通过关联复习和插件帮助你学习、研究与管理日程。**

四条产品主线：当前上下文感知、个人画像与学习状态、关联与间隔复习、可扩展的任务插件。

## 1. 感知当前阅读：有来源的上下文快照

用户阅读论文、网页、笔记或代码时，可以直接围绕当前内容提问。快照应保留内容来源、选区、页码或位置、捕获时间与发送范围，使回答依据可检查。

现有实现已经支持应用内文件或网页选区、当前文档、项目内容等上下文范围，发送请求时冻结 `ContextSnapshot`；代码编辑还可携带未保存缓冲区。当前能力范围是 CoScribe 内的阅读与编辑，系统其他应用的内容感知属于后续扩展，需单独设计采集范围和授权。

后续优先补齐阅读到学习的连接：用户可把选区加入知识点、文献笔记或复习材料，并保留原始来源。打开资料可以作为阅读事件；认定用户掌握知识还需要单独的依据。

## 2. 个人画像：身份、技术关注与学习状态

助理需要知道用户的身份、目标、当前关注的技术、学到哪里，以及掌握了什么技术。解释内容时结合这些信息调整深度，推荐资料时结合关注方向与学习进度。

现有个人记忆支持身份、偏好和目标，允许查看、纠正与遗忘。技术关注可作为用户声明的目标或身份信息记录，本轮 [学习与复习 MVP](./learning-review-mvp.md) 增加全局知识点、结构化关注／阶段／用户自评与独立复习证据；它们不能互相替代。每日复盘整理活动、用户报告和计划。

建议后端增加相互关联的数据对象，由个人助理和复习插件共用：

| 对象 | 最小字段与职责 |
| --- | --- |
| 知识点 | 稳定 ID、名称、所属领域、关联笔记或文献来源；笔记改名或卡片措辞调整后仍能关联 |
| 学习状态 | 知识点 ID、关注或学习阶段、用户自评、掌握依据、确认时间；区分自述与复习证据 |
| 知识关联 | 两端知识点 ID、关系类型、来源与确认状态；关系类型可从前置知识、组成关系、对比关系和应用关系开始 |
| 复习记录 | 知识点与卡片 ID、复习时间、反馈、下次到期时间、调度算法版本 |

用户明确表示掌握、完成自测或提交复习反馈，才能提供相应掌握依据。聊天次数、阅读时长和 AI 评价不能单独确立掌握状态。记忆引用时应保留依据与时间，并支持用户纠正。论文、网页和邮件是外部资料，进入资料库后仍不能自动成为用户身份或能力事实。

## 3. 复习插件：间隔安排与知识关联

目标闭环：知识点与学习依据 → 到期复习 → 回忆与反馈 → 更新学习状态与下次时间。个人助理提供学习上下文，复习插件负责队列、练习和反馈。

现有闪卡已有根据“重来、困难、良好、简单”反馈调整间隔的复习机制，但闪卡状态仍按项目保存，原记录保留为兼容来源；新版通过显式导入连接全局学习库，稳定 UUID、反馈事件与调度由后端持久化。“结合艾宾浩斯遗忘曲线”的产品要求落为可追踪的间隔复习：记录复习反馈，调整下一次时间，展示到期队列。MVP 不宣称能精确预测个人遗忘概率。每日复盘和知识复习各自保留用途：前者回顾做过的事，后者检查能否回忆知识。

关联复习需要围绕具体关系组织问题。例如学习注意力机制时，可以结合已学的矩阵乘法和 softmax 回忆计算过程；学习两种缓存策略时，可以通过适用条件与差异组织对比题。首版使用可检查的关联记录与来源，AI 提议的关系和题目经用户确认后采用。某个知识点复习成功只更新该知识点的记录，相关知识点的掌握状态仍需各自的依据。

首版前端只需要知识点列表、学习状态确认、今日到期队列、相关知识点入口和复习反馈。先完成打开应用后的到期查询与手动复习；后台提醒另行实现授权、时区、静默时段和通知去重。

## 4. 插件扩展：科研、日程与技术跟踪

各类插件共用上下文、记忆、来源追踪、任务状态、草稿确认与权限能力。插件提供功能界面和业务流程，Tool 暴露可调用的操作，Skill 可以组织工作步骤和提示词，MCP 可以连接外部服务；实际访问和写入仍由受限能力接口执行。当前插件仍是随应用发布的内置模块，尚未具备第三方动态安装或插件能力统一注册为 AI Tools 的机制。

### 科研工作台

目标闭环：研究主题 → 检索论文与 GitHub 仓库 → 筛选与导入 → 阅读与文献笔记 → 有来源的综述 → 知识点与复习。

现有 [Auto Research MVP](./auto-research-mvp.md) 已覆盖公开来源检索、元数据导入、尝试下载 PDF/README、笔记与综述草稿、预览确认保存。下一步优先提高任务可靠性：后端互斥、逐项结果与部分成功状态、跨文件导入日志和中断后核对。随后连接研究资料与学习状态，保留综述结论的证据范围和阅读缺口。

### 个人日程助理

目标闭环：读取授权范围内的邮件 → 提取待办或会议候选 → 核对时间、时区与冲突 → 用户确认 → 写入日程 → 跟踪变更。

现有项目计划插件能整理任务，并在授权后由用户操作写入 macOS 日历或提醒事项。邮件插件、邮件触发的日程流程，以及外部日程可靠同步尚未实现。

邮件首版应限定一个提供方、指定账户和时间范围，保留邮件来源及日期原文。外部写入必须记录操作 ID、目标事件 ID 和确认结果；结果不明确时先查询核对，避免重试创建重复会议。邮件读取、日历写入、回复邮件和发送邀请分别授权。邮件正文中的要求只作为待处理内容。

### GitHub 每周热点与技术跟踪

目标闭环：用户关注方向 → 有明确时间窗口的来源检索 → 去重与筛选 → 每周摘要 → 用户选择深入阅读、导入研究资料或加入学习目标。

首版可围绕用户配置的主题、语言或仓库生成按需周报，保留检索条件、统计口径、抓取时间和原始链接。周报需明确“最近创建且星标较多”“已关注仓库的发布动态”或“依据历史快照计算的星标增长”等口径；只有现有星标总数时不能声称取得了本周增长量，也不能标称 GitHub 官方 Trending 排名。摘要应说明与用户关注方向的关系，并标记资料尚未阅读或验证的部分。

当前 Auto Research 能检索公开 GitHub 仓库，网页跟踪插件能保存网页变化快照；每周热点汇总、跨周统计与个人技术订阅尚未实现。先提供手动生成，再实现用户选择周期的后台任务；任务需要持久化、去重、失败记录和明确通知设置。热点资料不会自动变成用户已掌握的技术。

## 后端优先的交付顺序

1. **打通个人学习状态与复习插件。** 完成知识点、技术关注、学习状态、关联记录的持久化与来源追踪，接入现有闪卡反馈和到期查询，支持纠正与删除。验收一条完整流程：阅读选区 → 知识点与关系确认 → 复习 → 更新下次时间 → 助理引用最新状态；关联练习不自动推定邻接知识点已掌握。
2. **补强 Auto Research 的任务可靠性。** 验收并发请求、部分下载失败、取消、崩溃后重试；资料、文献库与任务记录能核对，已成功的导入不重复覆盖。
3. **连接文献库、综述与学习记录。** 从文献笔记生成可编辑的知识点和复习材料，用户确认后进入队列；保留引用来源。
4. **实现单一邮件来源与日程候选。** 先完成只读提取与预览，再接入可核对的日历写入；随后增加后台提醒与变更跟踪。
5. **增加 GitHub 周报与技术跟踪插件。** 复用来源检索与任务记录，先实现关注配置、明确统计口径的按需周报，再实现周期执行和通知。

每一步只增加完成闭环所需的最小界面。现有记忆与每日复盘的实现边界见 [个人助理 MVP](./personal-assistant-mvp.md)。
