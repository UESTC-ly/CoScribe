# CoScribe 个人知识助理升级：产品与技术交接文档

> 状态：实施前设计与交接，不是已完成功能说明。版本：v1.0，2026-10-07。目标：先做好单用户、单台 Mac 的桌面应用。
>
> 本文综合本次需求讨论、当前工作树源码和公开一手资料。代码核对基线为 `package.json` 4.0.5，HEAD `472344db089c9ad49334e7a42c97ad4102694705`；工作树已有未提交修改，因此 HEAD 不能单独复现核对状态。本轮只新增本文，不修改应用代码、不安装服务、不授权邮箱、不创建实际自动化任务。

## 1. 接手者先读：目标、范围与完成标准

### 1.1 产品目标

将 CoScribe 从“资料阅读、AI 对话、笔记编辑工作台”，升级成**持续理解用户目标、基于个人知识提供帮助，并能安全推进学习与工作任务的个人知识助理**。

它应逐步理解用户明确提供的身份、表达偏好、正在学习的主题和当前目标；结合授权的笔记、长期对话、日程、邮件进行问答、提出安排、生成每日复盘，并在可控权限内完成整理和更新。

“越用越好用”首先通过有来源的记忆积累、纠正、适时召回和反馈迭代实现，不以训练或微调用户专属模型作为前置条件。不能把“记得更多”直接等同于“更了解用户”，更不能把模型生成的解释不断重新记成事实。

### 1.2 已确认的需求

1. 第一项升级方向改为个人知识助理 Agent，保留按需检索、读取和工具调用能力。
2. 建立动态用户画像与长期对话记忆，可查看、修正、删除和关闭。
3. 实现混合检索、结论与证据关联、可恢复任务与安全写入。
4. 支持日程导入或录入、基于日程问答、学习与任务安排建议。
5. 支持每日复盘，归纳实际记录的学习内容、成果、未完成事项和下一步。
6. 通过连接器或插件读取授权邮件，提取会议、截止日期等候选事项，确认后加入日程；后续支持有限规则自动化。
7. 参考腾讯 WorkBuddy、OpenClaw、腾讯 Marvis 的公开产品和工程机制，但不复制未经验证的内部架构假设。
8. 优先 macOS，不要求多端发布、云同步或手机遥控。

### 1.3 本轮不纳入的范围

- 多人协作、云端账户体系、多设备状态同步、远程控制电脑。
- 任意系统设置修改、全盘清理、无人值守 Shell、通用桌面操作 Agent。
- 自动回复或发送邮件、自动接受会议邀请、自动向他人发送日历邀请。
- 无限制第三方插件市场、自动安装 Skill 或 MCP 服务。
- 一开始就建设大型知识图谱、多 Agent 集群、自训练系统。
- 保证应用退出、电脑休眠或关机时仍能准点执行模型任务。

**边界原则：需求先于竞品。** WorkBuddy、OpenClaw、Marvis 仅作为已选功能的实现与交互参考，不是功能对齐目标。不能因为参考产品具备某能力，就把它加入 CoScribe 的里程碑。新功能必须说明它对应第 1.2 节的哪项需求、带来什么用户价值及验收方式；无法对应的内容进入独立讨论，不自动扩项。

| 已选 CoScribe 功能 | 可以参考的做法 | 不由此扩展的功能 |
| --- | --- | --- |
| 个人记忆与画像 | 分层、来源、更新、用户修正与删除 | 无限制采集全电脑行为、完整人物关系画像 |
| 知识库检索与整理 | 按内容找资料、任务进度、结果预览 | 全盘文件管家、系统清理、人像图库 |
| 日程与每日复盘 | 结构化事件、周期执行、低打扰提醒 | 云端全天候代管、手机远控、多端任务接力 |
| 邮件提取事项 | 连接授权、候选确认、去重与改期 | 通用邮件客户端、自动代发与客户关系管理 |
| 安全任务执行 | 明确步骤、审批、恢复、操作记录 | 通用系统操作 Agent、多 Agent 展示系统 |

完全离线大模型、全功能“隐私模式”、晨间简报等不是额外必交功能。本轮要求的是明确的数据出站控制；按日程给出建议属于已有需求，单独的晨报产品形态可在后续确认后加入。

### 1.4 三个标志性验收场景

**场景 A：持续理解用户。** 用户明确说正在准备某个目标、偏好某种解释方式。助理保存带来源的记忆；下次相关任务正确使用；用户纠正或要求忘记后，旧信息不再影响新回答。

**场景 B：邮件变成可管理的日程。** 读取授权邮件后提取会议候选，显示原文依据、时间和冲突；确认后只创建一次。后续改期邮件关联到原事件，形成更新提案，而不是再创建一个重复会议。

**场景 C：学习闭环。** 用户阅读、讨论和整理资料后，生成有证据的每日复盘，区分计划与实际活动；结合明日日程提出学习建议；新资料改变旧依据时，提示相关笔记复核并给出修改预览。

这三个场景应形成连贯体验，而不是各做一个互不共享状态的插件。

## 2. 外部产品参考：借鉴什么、不推断什么

### 2.1 参考资料的证据等级

- **源码核对**：本文对 CoScribe 当前行为的判断来自工作树代码。
- **公开设计文档**：OpenClaw 文档可参考其公开机制，但本次未运行或审计其完整实现。
- **官方产品说明**：WorkBuddy、Marvis 的产品文档可证明其公开描述的能力与交互；不能据此宣称已知其数据库、模型路由或容错实现。
- 不使用第三方营销介绍来证明技术架构，不假设其他产品的宣传指标能直接在本项目复现。

### 2.2 腾讯 WorkBuddy

官方记忆文档描述了从会话中提取个人事实、偏好与跟进事项，定期整理，并在后续请求中使用相关记忆；用户可以查看、编辑、删除或关闭。官方自动化文档描述了按时间规则运行任务、保存执行配置和历史，以及限制执行时长与并发。[WorkBuddy 记忆](https://www.codebuddy.cn/docs/workbuddy/From-Beginner-to-Expert-Guide/Function-Description/Memory)、[WorkBuddy 自动化](https://www.codebuddy.cn/docs/workbuddy/From-Beginner-to-Expert-Guide/Function-Description/Automation-Guide)

对 CoScribe 的启发是：记忆需要可管理的产品入口，周期性任务需要独立生命周期；“每天复盘”不能只表现成一段提示词。本文采用事件驱动的小步更新，加低频整理，而不是把所有画像更新都推迟到每天一次。自动化沿用独立权限和预算，不沿用无限权限。

这里的 WorkBuddy 指腾讯产品，不是域名为 `work-buddy.ai` 的另一产品。

### 2.3 OpenClaw

公开文档区分长期核心记忆、日常事件记录与用户模型，并记录来源类别和会话类型；记忆整理关注去重、替代关系及防止召回内容被再次提取。它还公开了周期性后台检查与活动时段控制。[记忆架构](https://github.com/openclaw/openclaw/blob/main/docs/concepts/memory-architecture.md)、[用户模型](https://github.com/openclaw/openclaw/blob/main/docs/concepts/user-model.md)、[Heartbeat](https://docs.openclaw.ai/gateway/heartbeat)

借鉴点：来源由程序记录，不能让模型通过生成文字“自证可信”；交互与后台任务区分来源；记忆整理和普通回答解耦；没有新情况时不反复打扰。

CoScribe 不直接嵌入整个 OpenClaw，也不照搬其网关、渠道和多用户架构。后台复盘与邮件提取采用独立任务上下文，不把外部输入伪装成用户消息，不允许后台模型输出自行升级为用户事实。

### 2.4 腾讯 Marvis（用户确认：marvis.qq.com）

官网与用户提供的官方介绍强调：任务拆解与交付、本地文件理解和内容搜索、低门槛使用、效率与本地隐私模式，以及风险操作确认。开发者的上架说明也介绍了任务分工和定时能力。[Marvis 官网](https://marvis.qq.com/)、[产品认知与定位](https://marvis.qq.com/docs)、[腾讯发布的应用说明](https://apps.apple.com/cn/app/id6776078618)

对本项目最重要的启发是三点：

1. **从问题走向交付。** 用户说“帮我整理这些资料”，助理需要定位资料、给出整理方案、生成预览并交付结果。
2. **按内容寻找资料。** 不要求用户记住文件名；找出相关片段后能够回到原文继续工作。
3. **低配置负担。** 常见任务内置入口，权限按需解释，不能要求用户先理解 MCP、向量库和 Agent 框架。

不照搬多端遥控、系统运维和全电脑访问；不从产品说明推断 Marvis 的索引、记忆或事务内部实现。所谓隐私模式必须由本项目的实际数据流验证，不能仅换一个开关名称。

## 4. 总体架构与核心约束

### 4.1 架构选择

保留 Electron + React + TypeScript，不重写 UI 技术栈。新增领域服务，通过现有 preload 和具名 IPC 接入。默认一个主 Agent 调用明确的领域工具；记忆抽取、重排、证据检查可以是受限模型任务，不必包装成多个相互对话的 Agent。

```text
用户请求 / 资料变化 / 邮件更新 / 定时触发
                    ↓
           来源登记 + 授权范围 + 去重
                    ↓
     Agent Runtime / 确定性工作流调度器
                    ↓
  记忆  ·  检索  ·  证据  ·  日程  ·  复盘
                    ↓
       修改提案 / 用户审批 / 写前日志
                    ↓
        文件服务 / EventKit / 连接器
                    ↓
          结果核对 + 恢复记录 + 展示
```

LLM 负责语言理解、候选提取、综合与建议。授权判断、路径校验、时间冲突、重复检测、状态转换和写入确认由代码强制执行。

### 4.2 不允许破坏的约束

1. Renderer 不获得 Node、文件系统、令牌、数据库或任意进程权限。
2. 新助理模式不得静默扩大原有“选区/当前文档”范围。用户画像、历史、邮箱、日历分别展示是否启用；个人助理入口有独立的授权范围说明。
3. 主进程创建来源与权限标签。模型不能提交任意 `owner=true`、`trusted=true` 来获得权限。
4. 当前用户的明确请求优先于旧偏好。记忆不是新的系统指令，也不授予执行能力。
5. 所有正文修改仍需预览确认；规则自动化必须有单独的有界授权，默认关闭。
6. 检索索引可重建；用户修正过的记忆、任务状态和操作日志不是可随便重建的缓存。
7. 资料读取失败时说明覆盖缺口，不能把缺失解释成“不存在”“已完成”或“今天没学习”。
8. 外部写入结果不明确时先核对，不能盲目重试，也不能宣称 exactly-once。

### 4.3 进程与生命周期

- 主进程负责权限、任务编排、连接器和系统桥接；数据库与索引重任务经专用 worker/受控子进程处理，避免阻塞窗口与 IPC。
- Swift EventKit helper 是窄接口系统适配器，不接受 Shell 字符串或任意 AppleScript。
- 每个任务固定 `workspaceId`、授权版本和项目生命周期标识。执行中切换项目，不能让任务转而访问新项目。
- 当前 `ProjectService` 以活动项目为中心，不能直接给后台多项目任务复用一个可变实例。第一版只允许明确绑定的项目任务；如要访问多个授权知识库，先增加按 workspace 获取独立只读上下文的服务。
- 关闭窗口不等于停止助理；菜单栏应显示后台状态。完全退出时取消模型请求、保存可恢复状态、停止连接器。

## 5. 数据模型、存储权威与迁移

### 5.1 存储方案

建议在 Electron `userData` 下新增本地 `assistant/assistant.sqlite`。路径通过系统 API 解析，不写死个人用户名，不把活跃数据库放入项目、Git 或 iCloud 同步目录。

普通 Markdown/PDF 仍是用户知识主文件。数据库保存个人记忆、活动、证据关系、任务日志、日程映射和可重建索引。凭据继续使用安全存储，不能写入数据库正文、提示词、Markdown 或诊断日志。

SQLite 可支持本地事务和全文索引；建议串行化写入，使用短事务、外键、唯一约束、版本迁移与一致性备份。WAL 不会让多个写操作变成无限并发，也不保证数据库与文件、系统日历一起提交。驱动与 Electron 成品兼容性先做技术验证，再锁定依赖。[SQLite WAL](https://www.sqlite.org/wal.html)

### 5.2 各类数据的权威来源

| 数据 | 权威来源 | 可生成的视图或副本 |
| --- | --- | --- |
| 笔记、原始资料 | 项目普通文件 | 索引、片段、摘要 |
| 个人画像、记忆修正 | 本地助理数据库 | 可读 Markdown/JSON 导出，不自动双向同步 |
| 既有项目记忆 | `.coscribe/COSCRIBE.md` | 作为用户维护的项目上下文；不自动覆盖 |
| 系统日历事件 | EventKit 所见系统日历 | 本地缓存、来源映射、问答结果 |
| CoScribe 原生待办 | 助理数据库 | UI、Markdown 导出、确认后的日历时间块 |
| 旧版 Markdown 计划 | 原文件 | 显式导入后成为原生任务；原文件不删除、不继续隐式双写 |
| 邮件 | 邮箱服务 | 授权范围内的缓存与候选事项 |
| 已接受复盘 | Markdown 文件 | 生成版本和证据映射 |
| 运行、审批、操作记录 | 助理数据库 | 用户可见任务历史 |

不要同时允许数据库、旧日程 Markdown 和系统日历无条件互相覆盖。导出不是同步；同步需要另设冲突协议。

### 5.3 核心实体草案

以下是概念字段，不是已经落地的数据库迁移。通用实体带 `id`、`schemaVersion`、`createdAt`、`updatedAt` 和适用的 `revision`。

| 实体/拟议表 | 必要字段 | 关键约束 |
| --- | --- | --- |
| `workspaces` | root 映射、授权状态、生命周期版本 | 移动路径不等于自动授予新目录权限 |
| `sources`、`source_versions` | kind、workspace/account、外部 ID、内容哈希、locator、observedAt、occurredAt、accessScope | 来源身份由程序创建；观察时间不冒充事件发生时间 |
| `chunks`、`embeddings` | sourceVersionId、文本、位置、chunkHash、模型/维度/切块版本 | 删除或撤权后不可召回；模型版本不能混用 |
| `memory_items` | subject、category、陈述、scope、status、validFrom/To、lastConfirmedAt、supersedesId | 推断不能冒充用户明确陈述 |
| `memory_evidence` | memoryId、sourceVersionId、quote/定位、提取器版本 | 来源标签不可由模型覆盖 |
| `memory_exclusions` | 被排除的来源/记忆链、作用范围、删除代次 | 阻止后台旧任务重新写回已遗忘内容 |
| `activities` | 类型、对象 ID、occurredAt、记录来源、dedupKey | 重复监听、导入和索引重建不产生伪学习活动 |
| `claims`、`evidence_links` | 笔记定位、结论、来源、支持/反驳/限定、验证状态 | 引用存在不等于语义支持 |
| `tasks` | 目标、dueAt、状态、预计耗时、优先级、来源 | 日程时间块不等于任务已完成 |
| `calendar_events`、`calendar_links` | calendarId、externalId、时间、时区、原始版本、operationId | 外部 ID 作为定位线索，不假定永远不变 |
| `mail_cursors`、`mail_candidates` | accountId、游标、messageId/threadId、提取版本、候选状态、关联事件 | 同一邮件候选不能重复提交；改期有独立版本 |
| `agent_runs`、`run_steps` | 目标、scope、预算、状态、lease、工具结果引用、checkpoint | 不保存隐式思维链；记录可观察行动与简短理由 |
| `approvals`、`operations` | payloadHash、基线、授权版本、前后状态、补偿状态 | 审批不能复用到变化后的参数 |
| `schedules`、`job_runs`、`review_runs` | 时区、规则、逻辑日期、资料水位、状态、输出引用 | 同一任务同一逻辑时刻具有唯一运行键 |

### 5.4 迁移与数据保护

1. 新功能先使用新数据库；不一次性迁移所有旧 JSON。
2. 导入旧会话、计划或项目记忆前显示范围，保留原文件；用源 ID、源版本和迁移版本做幂等导入。
3. 原始对话仍按现有方式保存，助理仅建立授权索引和事件引用。删除或退出授权时，相关衍生数据同步失效。
4. 新画像默认不从整个磁盘或所有旧会话自动生成；历史回填需要明确选择项目、时间范围并展示预计成本。
5. 迁移前建立一致性备份，失败回退到旧功能或只读模式；禁止把损坏的个人记忆数据库当作空库静默覆盖。
6. 导出/备份不含令牌。数据库、向量、原文摘录和日志都可能含敏感信息，必须列入隐私范围。系统安全存储保护凭据，并不自动加密整份数据库。
7. 第一版默认不持久保留整封邮件附件；正文缓存采用最小范围和可配置期限。用户选择严格本地策略后，模型、embedding、reranker 都不能偷偷转到云端。

## 6. 个人知识助理与长期记忆

### 6.1 记忆层次

- **画像**：用户明确提供的身份、研究方向、表达偏好。
- **目标与学习状态**：正在学什么、推进什么任务、哪些问题仍未解决。
- **事件记忆**：曾做的决定、完成的任务、讨论过的问题。
- **项目约定**：术语、写作规则、项目目标，限定在所属项目。

长对话摘要用于继续对话，用户画像用于个性化，知识库用于回答事实问题，三者不能混成同一种记忆。

### 6.2 更新机制

```text
消息/活动完成 → 提取候选 → 来源与主体校验 → 去重和冲突检查
            → 用户确认或已授权低风险更新 → 版本化记忆 → 相关时召回
```

明确的“记住/修改/忘记”请求优先处理。普通对话后的提取在后台排队，合并短时重复事件。若后台还未完成，当前用户陈述始终优先于旧画像，UI 显示更新状态，不宣称严格即时一致性。

规则要求：

1. 每条画像都可回查证据；提取器同时区分用户自述、引用、假设、他人信息和模型输出。
2. 知识库文章作者的身份、邮件收发人的身份不能自动变成用户身份。
3. 明确偏好更正可替代旧偏好；互不排斥的兴趣可以共存，不按时间简单覆盖。
4. “正在学习”有适用时间与复核机制；“已经掌握”需要用户声明或可解释的练习证据。
5. 后台摘要、模型自述、已召回的记忆不能作为新的独立用户事实反复累计。
6. 身份、关系和敏感推断默认进入确认队列；低风险学习状态自动更新需用户开启并可撤销。
7. 画像错误可退回上一版本，但不会因此撤销已经写入的笔记或日历。

第一版状态建议：`candidate`、`active`、`disputed`、`superseded`、`expired`。删除请求进入专门的遗忘流程，而不只是把显示状态改成隐藏。

### 6.3 召回与上下文预算

保留用户明确设置的少量偏好，按问题检索相关目标和历史事件；不要每次注入完整历史。检索结果带来源与时间，旧状态默认不参与当前建议，历史问题可以显式查询过去状态。

权限过滤必须发生在候选召回、重排、上下文拼装之前。关闭个人记忆后，不应仍从“历史检索”路径偷偷带入被禁止的个人信息。

设置记忆查询超时与独立 token 预算；失效时继续普通问答，并说明未使用长期记忆。不得为了补足上下文自动扩大项目或邮箱范围。

### 6.4 遗忘与防止复活

用户删除后，要同步处理活动画像、检索索引、摘要缓存、向量、待处理候选和后台队列。存最小必要的来源排除或替代标识，防止旧任务再次写回；不要为了记住“忘记了什么”又保留完整敏感陈述。

提交后台结果前检查授权版本和删除代次。用户可选择仅忘记助理记忆、同时排除其原始对话来源，或进一步删除可管理的原始记录；这三种行为必须解释清楚。

遗忘不等于能从用户已导出的 Markdown、系统备份或第三方邮箱中物理擦除所有副本。已有备份的删除边界、缓存回收和新请求中的不再使用应分开说明。

## 7. 混合检索与有界 Agent 搜索

### 7.1 检索管线

1. 文件按结构切块，保留标题路径、页码、段落和父子关系。
2. 关键词与向量分别召回，先做权限和状态过滤。
3. 用 RRF 等按名次融合的方法建立初始候选；不直接相加不同量纲的分数。
4. 对候选重排、去重、控制单文件占比，按 token 预算组装证据。
5. 证据不足时，Agent 可有限改写查询、读取命中片段的邻近章节或原页。
6. 达到预算仍不足时明确报告，不靠模型补造结论。

保留当前词法检索作为基线和降级路径。文件名、方法名、编号等精确查询不必经过完整多轮探索。

### 7.2 中文、结构与增量更新

SQLite FTS5 可作为词法检索实现候选，但默认 tokenizer 不能直接当作中文分词方案。需要评估中文分词/字词组合索引，并保留短词精确匹配；单纯 trigram 对少于三个字符的全文查询存在限制。[SQLite FTS5](https://sqlite.org/fts5.html)

索引键包含来源版本、内容哈希、切块版本和 embedding 模型版本。只重算变化片段；构建中再次变更的资料不能被旧任务覆盖成最新。新索引完整后再切换 generation，旧版本在过渡中只读。

PDF 优先复用文本层与已生成 OCR；扫描件没有可读文本时报告覆盖缺口。正文检索先完成，图像语义检索和复杂表格理解作为后续增强，不为了接近 Marvis 而阻塞核心任务。

向量存储第一版不引入独立服务。通过本地接口选择经成品验证的方案；先测实际数据量和延迟，再决定是否需要近似索引。模型更换后重建相应向量，不混合不同维度或语义空间。

### 7.3 检索对象分区

知识资料、用户记忆、历史对话、邮件、日程分别标注类型。对日程事实优先执行结构化查询，不用向量相似度代替时间查询。资料检索与个人信息召回可组合，但不能因此混淆事实主体与来源权威。

## 8. 结论—证据—笔记关联

### 8.1 第一版要实现的关系

每条重要结论绑定笔记段落与来源片段，记录“支持、反驳、适用条件”。引用包含源版本、原文摘录和定位，不只保存文件路径与行号。

文件编辑导致行号漂移时，结合内容哈希、标题路径、引用原文和前后文重新定位；失败则标记引用失效，不静默跳到另一段内容。源文档删除或撤权后，回答不得继续使用缓存中的敏感摘录。

### 8.2 来源变化后的行为

来源变化 → 标记依赖关系待复核 → 校验引用位置 → 必要时进行模型辅助语义检查 → 生成受影响段落的修改建议。

内容哈希变化不等于旧结论错误；新增资料与旧结论不同，也可能是实验条件不同。必须保留“不确定”和“限定条件”的表达，不能自动宣布冲突已解决。

### 8.3 验证与写入

程序检查来源存在、版本、引用范围与原文匹配；模型辅助判断支持关系并给出证据，重要结论仍可人工复核。只修改用户接受的段落，保留用户自己的分析和结构。第一版使用关系表，不引入图数据库，也不宣称具备完整 GraphRAG。

## 9. 日程、任务与学习建议

### 9.1 模型与计算职责分离

- 程序负责指定时间范围查询、空闲区间计算、冲突校验、截止日期与时区转换。
- 模型负责理解目标、解释优先级、生成候选安排和调整建议。
- 候选安排再交给确定性规则检查，用户确认后写入。

开始/结束时间、时区、全天事件、暂定状态、可用性、用户工作时间和缓冲间隔都要进入模型。没有结束时间的任务不能直接当作固定时长会议；估算耗时须明确标注。

日程不完整或账号离线时，回答应为“在当前已同步日历范围内未发现冲突”，不能保证用户现实中有空。

### 9.2 macOS EventKit 适配

建议通过随应用打包的 Swift helper 或经过验证的原生桥接调用 EventKit。先做读取、创建、回读、更新、删除与权限拒绝的最小成品验证，再决定具体桥接方式。日历查询需要相应读取权限，不能只请求写入权限。[Apple 日历访问](https://developer.apple.com/documentation/eventkit/accessing-the-event-store)

要求：

- 展示用户选择的可读日历和可写目标；不沿用“默认写入第一个可写日历”的隐式行为。
- 第一版只允许创建或维护 CoScribe 管理的非邀请事件；不修改任意已有会议、不发送参与者通知。
- 监听系统变化后刷新关心的时间范围，刷新权限或资源失效状态；不能把变更通知当作完整差量事件。[Apple 变更通知](https://developer.apple.com/documentation/EventKit/updating-with-notifications?language=objc)
- 保存外部事件 ID、时间/内容版本与本地 operationId；ID 失效后按受限窗口和关联标记对账，不能只按标题匹配。
- 日历与提醒事项分别申请权限，用户只授权其中一项时允许部分功能运行。
- helper 只接受校验后的结构化请求，输出有版本的 JSON；参数不经 Shell 拼接。

### 9.3 第一版范围

支持单次事件、全天事件、待办及截止时间、查看已有重复事件的发生项。复杂重复规则创建、修改系列中的单次例外、邀请响应和跨日历移动暂缓。

旧 Markdown 计划继续可用。用户主动导入原生任务时显示映射和差异，以迁移指纹防重复；不推断已有系统事件一定由该 Markdown 行创建。

## 10. 邮件连接器与日程候选

### 10.1 连接器选择

首个真实邮箱服务由用户确认；未确认前用脱敏 `.eml`、`.ics` 和 mock connector 完成领域逻辑，不阻塞开发。Gmail 可作为首个技术验证候选，但不是用户已经选定的服务。

连接器应提供身份、能力清单、分页/增量同步、指定邮件读取、撤权和健康状态。MCP 可以作为适配来源，但必须归一成相同的来源、权限和错误契约；首版不把未知 MCP 服务直接接进无人值守工具循环。

对 OAuth 型服务使用官方支持的桌面授权方式，在系统浏览器登录；令牌由主进程安全保存，不暴露给 Renderer 或模型，不读取用户浏览器 Cookie。不同邮箱的 API、IMAP 或授权码规则应按服务分别验证，不能假设全部相同。[Google 桌面授权](https://developers.google.com/identity/protocols/oauth2/native-app)

### 10.2 同步与失败恢复

首次只同步用户选择的时间/文件夹范围；保存游标后增量同步，批次成功落地后才推进游标。同一 `accountId + messageId + sourceVersion` 去重，重试不重复生成候选。

Gmail 的 `historyId` 失效可能返回 404，需在原授权范围内重新同步；其推送机制依赖 Cloud Pub/Sub。第一版采用运行期间的低频增量拉取和唤醒补同步，不引入公网 webhook 服务。[Gmail 同步](https://developers.google.com/workspace/gmail/api/guides/sync)、[Gmail 推送](https://developers.google.com/workspace/gmail/api/guides/push)

断网、限流、令牌过期和权限撤销分别处理；连接器失败不阻止本地问答。显示最后同步时间和覆盖范围，避免把旧缓存当作完整最新邮箱。

### 10.3 候选提取规则

1. 优先解析标准邀请及其事件标识、版本、取消信息；没有结构化邀请时再提取正文。
2. 保存标题、时间、时区、地点、会议链接、是否涉及本人、原文证据及缺失字段。
3. 正文相对日期结合邮件发送时间、上下文和时区解析；“下周五”“下午三点”有歧义时询问，不用当前运行日期随意猜测。
4. 区分已确认会议、邀请、待定时间、截止任务、广告宣传和转发通知。
5. 后续改期/取消关联已有候选或事件；同一 thread 可能有多个会议，不能只按 thread 合并。
6. 会议链接作为数据展示，不自动打开或抓取任意 URL。邮件 HTML 去脚本和远程图片，附件有类型与大小限制。

候选状态建议：`new`、`needs_clarification`、`ready_for_review`、`approved`、`applied`、`dismissed`、`superseded`、`failed`。候选生成后 UI 展示提取依据和冲突，用户可修改再确认。

### 10.4 自动化权限

默认只提取候选。后续可允许用户制定明确规则：指定账号/来源、事件类型、时间范围、目标日历、每日数量上限和禁止冲突条件。仅发送者名字或模型置信度不足以成为自动执行授权。

默认禁止自动改期、取消、修改他人会议或发送任何通知。新增到私人日历也不等于接受邀请；UI 与工具名称必须区分这两种操作。

邮件里的个人信息进入候选事实，不自动确认为用户身份。邮件中的指令一律是外部内容，不能授予删文件、导出资料或运行命令的能力。

### 10.5 发布与数据共享风险

Gmail 只读正文权限也属于受限权限。个人测试、组织内部使用和公开发布分别核对适用要求；是否把邮件内容发送给远端模型也影响评估。不要承诺“只做 Mac 就没有审核或隐私问题”。[Gmail 权限说明](https://developers.google.com/workspace/gmail/api/auth/scopes)

第一版可以先把邮件原文留在本地、仅按授权读取必要片段。严格本地策略下不允许云端提取；本地模型不可用时允许用户手动处理，不能静默切换云端。

## 11. 每日复盘、次日建议与低打扰主动性

### 11.1 活动事实来源

记录用户允许的应用内活动：相关对话、实质笔记修改、阅读完成标记、闪卡结果、任务完成和手动补充。活动带原始来源与发生时间。

禁止以下推断：打开文件即学会、修改时间即学习时间、导入旧笔记即今天新学、计划会议即已参加、无人记录即没有学习。第一版不做全局屏幕录制、键盘监控或隐式跨应用行为追踪。

### 11.2 复盘工作流

选定用户时区中的日期窗口，冻结输入水位，聚合授权活动和计划状态，生成复盘草稿：

- 实际记录的学习与工作内容。
- 形成的新笔记、结论与来源。
- 已完成事项和未解决问题。
- 计划与实际的差异，说明数据缺口。
- 结合明日日程提出的建议。

草稿每条重要事实关联活动或资料；生成的计划不混入“已完成”。用户补充线下活动后可重新生成，但保留人工段落。

### 11.3 保存与重复执行

默认在助理库生成草稿，导出到用户选择的项目位置时走现有确认写入。项目每日笔记只汇总该项目授权内容；跨项目个人复盘需明确选择输出位置，并预览是否包含个人邮件/日历信息，避免把私密信息写进可分享仓库。

复盘以“用户、日期、时区、工作流版本、输入水位”识别生成版本；同一输入重试不重复追加。使用显式管理区块或块 ID 更新 AI 部分，不覆盖用户编辑。已有当日笔记必须先读再生成提案。

复盘文本属于模型产物，不能整篇反向升级为新用户事实。任务完成等结构化真实事件可经记忆规则更新状态。

### 11.4 调度策略

区分三种触发：事件驱动同步、每日固定复盘、低频关注检查。确定性的“有没有新邮件/到期任务”先由程序检查，有相关变化才调用模型。

支持启停、时区、活跃时段、免打扰、预算、上次执行结果和补执行策略。启动或唤醒后只合并处理必要的遗漏任务，不一次弹出多天重复通知。通知失败不回滚已生成的成果，通知内容默认不展示邮件正文或敏感身份。

第一版不安装常驻 launch agent。完全退出后停止；重新启动再补执行。操作系统通知可作为提醒，但不意味着后台模型任务已经运行。

## 12. Agent Runtime、工具与安全执行

### 12.1 工具契约

建议先提供有限工具族：

| 工具族 | 示例能力 | 默认权限 |
| --- | --- | --- |
| 知识读取 | 搜索、读取片段、展开来源、查反向链接 | 当前授权知识范围内只读 |
| 记忆 | 召回、提出新增/修正、显式遗忘 | 检索与持久化分权 |
| 日程 | 查询、计算空闲、提出安排 | 读取；写入进入提案 |
| 邮件 | 查询指定范围、读取指定邮件、生成候选 | 只读，无发送工具 |
| 笔记 | 生成变更集、查看差异 | 提案不写盘 |
| 复盘 | 收集当日活动、生成草稿 | 草稿权限；正文写入另批 |

每个工具声明输入/输出 schema、来源类型、权限、超时、最大结果长度、副作用等级、是否可安全重试和幂等策略。工具结果统一带 `sourceRefs`、`observedAt`、`scope`、`truncated` 和明确错误类型。

模型选择工具不等于获得权限。执行器在调用前重验授权、项目身份、路径和数据发送策略。工具集按任务最小化加载；首版个人助理不开放任意 Shell、SQL、HTTP URL 或动态代码执行。

### 12.2 状态机与模型适配

运行状态：`queued → running → waiting_approval / waiting_input → running → succeeded`；也可进入 `cancelled`、`failed`、`needs_reconcile`。成功必须有可核对结果，不能仅以模型结束输出为准。

沿用现有 provider 适配，新增归一化的多工具调用/结果结构，保留 toolCallId 关联、流式取消、错误和用量统计。不要将当前“只处理首个工具调用”的分支外面简单套一个 while 循环。

运行设置总步数、总 token、耗时和重复调用预算。只读工具可有限并发，有副作用的操作按对象串行。模型计划作为可修订任务说明，不保存或展示隐式思维链。

### 12.3 审批与写前日志

审批绑定具体变更内容哈希、目标、原始版本、权限版本和适用期限。等待确认期间内容或权限变化，旧审批失效。自动化使用用户明确创建的规则授权，也须在每次执行时复核。

副作用流程：持久化 `prepared` 意图与必要恢复信息 → 执行前复验 → 外部/文件写入 → 回读核对 → 记录 `committed`。这是一套可恢复协议，不是跨系统原子事务。

对于崩溃后状态不明确的操作：

| 当前观测 | 恢复决策 |
| --- | --- |
| 文件仍等于 before | 在授权仍有效时可重新执行 |
| 文件等于预期 after | 记录已完成，不重复追加 |
| 文件既不是 before 也不是 after | 标记冲突，保留数据并等待用户处理 |
| 日历可定位到匹配 operationId 的事件 | 核对内容，补记成功或提出冲突 |
| 外部结果无法可靠定位 | `needs_reconcile`，禁止盲目创建第二次 |

多文件变更记录每一步，失败尝试逆序补偿；补偿前检查当前版本，不能覆盖新编辑。部分成功、补偿失败和等待人工处理必须明确展示。

### 12.4 调度并发与撤销

使用持久化队列、租约与执行代次；重启后过期运行先核对副作用再恢复。租约防止两个 worker 同时执行，并不能证明外部操作只执行了一次。取消请求也可能发生在副作用已经成功之后，UI 要返回真实状态。

本地正文沿用并增强现有撤销。日历撤销是一次新的受控外部修改，只操作本应用管理且未被外部改变的事件；不能直接套用 JSON 正文历史。邮件第一版只读，无自动删除或回信需要补偿。

## 13. 权限、隐私与威胁模型

### 13.1 最小授权矩阵

| 能力 | 默认行为 | 扩展授权 |
| --- | --- | --- |
| 当前文档问答 | 维持现有范围 | 用户主动扩大范围 |
| 跨知识库检索 | 关闭 | 逐目录选择，可撤销 |
| 个人画像 | 首次使用说明并选择 | 明确自述更新；推断候选确认 |
| 历史回填 | 关闭 | 时间、项目、成本范围确认 |
| 邮件 | 未连接 | 指定账号与读取范围，不含发送 |
| 系统日历 | 未连接 | 选择读取范围和专用写入日历 |
| 自动加入日程 | 关闭 | 有界规则、数量上限、可审计 |
| 每日复盘 | 手动草稿 | 用户设定周期与输出范围 |
| 云端模型处理个人信息 | 按功能说明 | 按数据源/任务明确允许；本地策略不可自动降级 |

### 13.2 必须覆盖的攻击与误用

- 邮件、网页、PDF、笔记中的提示注入要求修改记忆、发送资料或扩大权限。
- 模型把外部文本重述后洗成“用户说过的事实”。
- 恶意路径、符号链接与项目切换导致越界访问。
- MCP 工具描述与实际副作用不一致；不能仅信任其 `readOnly` 声明。
- 邮件附件或链接触发任意 URL 请求、本地文件读取或远程追踪。
- 画像删除后，旧缓存、索引、自动任务或导入再次恢复已删除信息。
- 诊断日志、截图、数据库备份或复盘导出泄露私密正文。

安全依赖程序边界和权限裁剪，不依赖“提示词已经要求模型不要泄露”。保留现有 sender 校验、contextIsolation、sandbox、窄 IPC 与项目路径守卫。未来若接第三方进程，应用层路径检查不等于 OS 沙箱。

## 14. 模块落点与开发接入清单

下列目录是拟议新增结构，不表示文件已存在；按职责逐步拆出，避免把所有逻辑继续塞进 `ai.ts` 和 `project.ts`。

```text
electron/main/assistant/
  runtime/       # 运行、工具注册、步骤、预算、取消与恢复
  policy/        # scope、来源、审批、数据出站策略
  storage/       # 数据库、迁移、备份、repository
  memory/        # 候选提取、冲突、遗忘、召回
  retrieval/     # 切块、词法/向量、融合、重排、索引版本
  evidence/      # 引用锚点、结论关系、失效与复核
  planner/       # 任务、时间约束、安排建议
  review/        # 活动聚合、每日复盘、人工内容保护
  scheduler/     # 周期规则、补执行、去重、通知
  connectors/    # 邮箱适配器、日历适配器、MCP 归一化
native/macos/    # 拟议 EventKit helper，先完成打包验证
src/shared/     # 助理领域 DTO；保持现有类型入口兼容
src/components/assistant/  # 任务状态、来源和审批展示
```

接入规则：

1. `electron/main/index.ts` 负责装配和退出清理；新增服务不隐式依赖当前 UI 选中的项目。
2. `electron/ipc-channels.ts`、`electron/preload/index.ts`、`src/shared/types.ts` 和主进程 handler 同步修改，运行时 schema 校验不能省略。
3. `ai.ts` 保留协议适配入口，逐步将任务编排委托给 runtime；旧普通聊天路径可回退。
4. `project.ts` 继续作为已有文件安全边界，新执行器调用它或提取后的同等守卫，不绕开它直接写盘。
5. 扩展 `PluginPermission` 时区分读取、提案、提交和个人数据范围，不能只增加一个笼统 `assistant:all`。
6. 日程和每日笔记插件复用领域服务；助理聊天和插件页面必须看到同一状态，不各自维护一份任务库。

面向用户至少需要“助理首页、关于我、日程、待确认事项、每日复盘、连接与隐私、运行历史”这些入口。它们是信息组织要求，不要求新增七个顶级页面；应复用现有工作台和侧栏，后续再做具体交互设计。

## 16. 测试、评测与验收

### 16.1 必须全通过的确定性回归

1. 阅读或检索范围不能因助理模式静默扩大。
2. 外部邮件中的指令不能修改画像、开启新权限或触发任意工具。
3. 更正后的记忆不被旧候选覆盖；遗忘后的信息不从旧队列或索引复活。
4. 不同项目、邮箱账号和数据出站策略互不串用。
5. 已撤权的来源不能经摘要、缓存或向量继续召回。
6. 同一任务、邮件候选、日历操作或复盘重试不产生重复成果。
7. 预览后文件变化时拒绝旧写入；撤销不覆盖后续人工编辑。
8. 每个副作用边界强制终止进程，恢复后能识别 before/after/unknown 三种状态。
9. 等待审批期间重启、修改参数、撤权时，旧审批不能无条件生效。
10. 夏令时、跨午夜、全天事件、时区切换、同名会议与缺失结束时间处理符合约定。
11. 断网、超时、429、令牌过期、游标失效、日历权限拒绝都有明确状态和降级。
12. 复盘保留人工正文，不能把计划任务或历史导入当成今日已完成学习。

“测试集无违规”只说明该测试集通过，不等于系统绝对安全。

### 16.2 模型质量评测

建立脱敏、固定版本的评测夹具，建议起步规模为 50 个知识查询、30 组记忆更新序列、30 组邮件邀请/改期/取消、20 组复盘活动。数字是启动建议，不是当前已有数据。

| 模块 | 指标 | 对照方式 |
| --- | --- | --- |
| 检索 | Recall@K、MRR、短词/同义词分组结果、p50/p95 延迟 | 旧词法 → BM25 → 混合 → 重排 |
| 记忆 | 提取精确率、主体误归属、矛盾残留、过期召回、纠正/遗忘遵从 | 无记忆、简单摘要、版本化来源记忆 |
| 证据 | 引用定位正确率、结论支持率、来源失效检出 | 程序校验 + 人工抽查 |
| 邮件 | 时间/时区字段准确率、本人相关性、改期关联、重复事件数 | 结构化邀请与正文分别评估 |
| 复盘 | 事实支持率、活动覆盖、计划与实际混淆、人工内容保留 | 原始活动账本对照 |
| Agent | 任务完成率、人工确认次数、模型调用数、token、成本、恢复成功率 | 相同模型、资料、权限和预算 |

确定性结果用程序判断；开放文本用明确量表、模型辅助和人工校准。不要只让模型自评分，也不要只展示一个成功演示。性能目标需绑定 Mac 型号、资料规模、模型与冷/热缓存条件后设定。

```bash

npm run test:e2e
npm run dist:mac:arm64
npm run verify:package:mac
```

实现时先运行聚焦测试，再按影响范围运行完整测试。现有相关测试包括 [上下文测试](../electron/main/ai-context.test.ts)、[文件操作测试](../electron/main/project-ai-operations.test.ts)、[索引测试](../electron/main/knowledge-index.test.ts)、[日历测试](../electron/main/calendar.test.ts) 和 [MCP 测试](../electron/main/mcp.test.ts)。

## 17. 发布、回退与接手行动

### 17.1 macOS 发布边界

暂以现有 arm64 打包链路作为优先验证目标；最低 macOS 版本、是否兼容 Intel 在 M0 确认，不能把其他产品的系统要求直接套到 CoScribe。

EventKit helper、SQLite/向量依赖及本地模型运行时要检查打包路径、签名、权限说明和退出清理。保留已有工作台功能；关闭新助理功能时，普通阅读、编辑和聊天仍可使用。

按功能开关逐步开放记忆、日历、邮件和自动化。连接器或模型不可用时显示具体缺口，不把整个应用锁住。版本降级不可用旧程序直接写入未知新版 schema；提供恢复备份或只读导出路径。

### 17.2 技术决策与待确认项

| 项目 | 当前结论 | 下一步 |
| --- | --- | --- |
| 产品与平台 | Mac 个人知识助理，已确认 | 不扩展多端 |
| Marvis 身份 | 腾讯 `marvis.qq.com`，用户已确认 | 使用官方资料，不混淆同名产品 |

| 系统日历 | 建议 EventKit，选择范围和专用目标 | 在签名成品中验证权限与 helper |
| 首个邮箱 | 尚未选定 | 询问用户实际邮箱，先完成 mock |
| 模型策略 | 沿用现有 provider；支持数据源出站约束 | 选择 embedding/reranker 与本地能力后评测 |
| 自动记忆 | 建议默认告知与选择，推断保守 | 用户测试自动更新的接受程度 |
| 自动加入日程 | 首版关闭，后续规则授权 | 基础准确率与恢复测试达标后开放 |
| 后台常驻 | 应用运行期间支持，退出后不保证执行 | 菜单栏和启动/唤醒补执行 |
| 多 Agent | 不是首版必要条件 | 仅在测得并行收益后另立方案 |

### 17.3 接手者的第一批动作

1. 阅读仓库 `AGENTS.md`，检查 `git status`，保留现有未提交代码和文档，不恢复、不覆盖、不顺手提交。
2. 复核第 3 节实现基线，并记录实际运行的测试结果；不沿用历史通过数字。
3. 将本文的安全约束与三个验收场景转成测试夹具，先冻结基线。
4. 完成 M0 的数据库/中文检索与 EventKit 技术验证；先用 mock 邮箱。
5. 创建 M1 最小纵向切片：用户明确记住 → 来源持久化 → 后续相关召回 → 更正/遗忘 → 重启仍正确。
6. 第一批实现不要同时重写 `ai.ts`、`project.ts`、全部插件和存储；每步可回退并保留旧功能。
7. 每次交接更新“完成、未完成、风险、迁移、测试证据、下一步”，不要把设计意图改写成实现事实。

## 18. 最终交付定义

项目的技术主线不是“增加多少个 Agent 或连接多少个 MCP”，而是四个可验证的能力：

1. **持续理解用户，但可以解释、纠正和遗忘。**
2. **基于资料给出有来源的回答，并维护结论与证据的关系。**
3. **结合日程、邮件和真实活动推进任务，而不是只生成建议文字。**
4. **所有副作用有权限边界、结果核对和恢复路径。**

M1—M5 完成后应交付：可安装 Mac 应用、受控演示数据、三个端到端演示、可重复运行的回归与质量评测、数据迁移/导出说明、权限与隐私说明、已知限制和真实测试记录。本文交接完成不代表这些实现已经交付。
